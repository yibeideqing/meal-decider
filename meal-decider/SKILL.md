# Meal Decider

帮用户在“不知道今天吃什么”时，从现有食材出发做决定，而不是给菜谱大全。

## 触发与不触发

- 触发：用户在为“做什么菜”做选择，并给出了食材、忌口或口味中的至少一项。
- 不触发：用户已知菜名只问做法 → 直接教做法；只问营养知识 → 直接回答；挑餐厅或外卖 → 本技能不适用。

## 工作流程

1. **解析输入**：食材清单（必填）、忌口/过敏（选填）、口味偏好（选填）。把口语食材归一成烹饪中的叫法，同一食材的不同叫法视为一种（如“剩米饭”=“米饭”，“西红柿”=“番茄”）。
2. **食材清单是唯一必填项**：清单缺失、或完全无法据此匹配任何菜时，先问一个简短问题（把你能猜到的常见食材列出来让用户确认），不要凭空硬编菜单。
3. **其余信息缺失不追问**：口味、份量、克数、调味自己按常见家常做法假定。用户说“随便”“你看着办”只是不限定口味，直接给建议，不要再确认一遍。
4. **先过滤再匹配**：先用忌口排除全部不合规的菜，再在剩下的里按口味偏好排序，选出 2-3 道。若用户列出的食材本身与其忌口冲突（例如说海鲜过敏却列了虾），直接指出这个冲突并剔除该食材，不要拿它做菜。
5. **排序标准**（依次）：能消耗掉用户列出的食材，尤其是叶菜、豆制品、剩饭剩菜等不耐放的 → 步骤少、家常做法 → 几乎不需要额外采购。

## 每道菜要给出的内容

- 菜名
- 食材：分“已有”和“需补”两行。默认家里有基础调味料（油、盐、生抽、醋、糖、料酒、葱姜蒜），这些不算“需补”；完全不用额外采购就写“无需额外采购”
- 步骤：3-5 步，每步一句话，只写关键顺序和火候，不要展开成长篇菜谱

## 输出格式

先写“根据你的食材和偏好，推荐这几道菜：”，再分条列出每道菜，最后以“想先做哪一道？我可以给你更详细的步骤。”收尾。如果需要先提醒冲突（如口味与忌口冲突、所列食材与忌口冲突），这段提醒放在开场句之前。

```
根据你的食材和偏好，推荐这几道菜：

1. 番茄炒蛋
   已有：鸡蛋、番茄
   需补：无需额外采购
   步骤：1) 鸡蛋加少许盐打散，热油炒至凝固盛出。2) 番茄切块下锅炒出汁。3) 倒回鸡蛋，加盐和少许糖翻匀。

2. ...

想先做哪一道？我可以给你更详细的步骤。
```

## 硬约束

- **忌口是不可协商的过滤条件**，绝不能出现用户明确排除的食材。注意隐性成分：海鲜过敏要排除蚝油、鱼露、虾皮、海苔、蟹柳、虾米；不吃辣要排除辣椒、豆瓣酱、辣油、泡椒、小米辣；不吃猪肉要排除培根、香肠、猪油。拿不准某样食材或调料是否落在忌口范围内时（如“不吃辣”是否包含青椒），先避开并在菜里说明，不要赌运气。
- 不要推荐需要大量额外采购的菜，除非用户明确说“可以买”。需补的食材以 1-2 样为限，并尽量是常备调料。
- 口味与忌口冲突时（如“想吃重口味”但“不吃辣”），先明确指出冲突，再给折中方案（用咸鲜、酱香、蒜香、焦香替代辣味），不要偷偷忽略忌口来满足口味。
- 食材实在不够时，如实说明“这个组合可能做不出完整的菜”，并只列出最少需要补的 1-2 样。
- 用户列出的食材明显用不完时不用硬凑，可以指出这次用不上哪几样，并优先消耗易坏的。
